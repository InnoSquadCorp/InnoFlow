## Findings and validation

The original implementation failed four new diagnostic controls: edited-base
planning was unsupported, case variants of reserved labels selected weaker plans,
empty Ready targets still allocated a planner, and non-PR CI notifications still
allocated the inspector. The same controls now pass. General labels and title/body
edits now skip the complete CI graph under a separate concurrency identity; base
retargets and both reserved validation labels retain real validation. Neither
protected aggregate is emitted under its required name by a metadata-only run.

Metadata no-ops cannot serve as validation proof. The shared verifier binds the
workflow blob, test-merge parents, job/check IDs, complete skipped inventory and
all attempts before excluding a run. Completion only wakes revalidation of real
CI and native Ready. Adversarial fixtures cover pending/failed/cancelled real CI,
forged no-ops, changed source, stale attempts, recovery while Ready is already
successful, and protective cancellation after actual CI fails.

Pinned actionlint runs inside the existing policy job. Archive checksum and
regular-file checks, bounded downloads and exact-position queue compatibility
exceptions are enforced. InnoFlow already had complete runner timeouts and
job-scoped Pages concurrency, so those protections are retained. Existing cache,
API/migration, compiler, sanitizer, coverage, platform/sample and release checks
retain their owners and thresholds.

## Hosted metadata verification — PR #52

An actual PR description edit exposed one representation difference from local
fixtures: GitHub records a skipped dynamic aggregate name as the expression
source without `${{ }}`, rather than its evaluated display name. The original
metadata verifier rejected this valid no-op. The fix recognizes only the exact
reviewed native expression in addition to its evaluated name, retaining every
workflow/merge/attempt/job/check binding. Workflow-derived inventory tests now
cover all combinations, with forged expressions rejected.

Read-only execution of the corrected verifier against live GitHub API evidence
accepted metadata runs **37026415972, 37026559418** (attempt 1), accounting for
**40 native skipped checks**. The original real CI run **37026323672** remained
queued and was not cancelled. No metadata run allocated an execution job or
published either a CI success proof or a protected aggregate under its required
name. These observations bind to the first PR candidate; the workflow YAML is
unchanged by this verifier correction. Full final-candidate CI, genuine bot
arming/recovery after merge and realized timing savings remain unverified.
